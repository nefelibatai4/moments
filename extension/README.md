# Moments 私密圈 · Chrome 扩展

工具栏角标显示未读私信；点一下图标，当前网页上会浮出一层**毛玻璃面板**，
背后是你正在看的网页（模糊可见），面板里就是 Moments 本体，**不用切标签页**就能看动态、回私信。

> 0.2.0 起面板从「action 弹窗」改成了「注入到当前网页的浮层」。
> 原因：Chrome 的插件弹窗是浏览器自己画的独立小窗，**窗口不透明**，
> 网页拿不到透明/模糊的权力，`backdrop-filter` 在弹窗里没有可采样的背景 ——
> 也就是说"透出背后的网页"这件事在弹窗形态下**做不到**。
> 改成浮层之后它是网页文档的一部分，`backdrop-filter` 模糊的就是真实网页内容。

## 安装

Chrome 无法从网页直接安装扩展，需要走「加载已解压的扩展程序」（一次性，约 1 分钟）：

1. 打开 `chrome://extensions/`
2. 右上角打开 **开发者模式**
3. 点 **加载已解压的扩展程序**
4. 选择扩展目录：开发时是 `~/moments/extension`；
   从 Moments 网页【我】页面下载的压缩包，解压后是 `moments-extension/`，选它即可

装好后建议点一下工具栏的拼图图标，把 Moments **固定**到工具栏——不固定的话角标看不见。

## 首次使用

**不需要在扩展里登录。** 打开一次 Moments 网页（正常登录），扩展会自动把会话同步过去，之后就一直有效。

同步成功的标志：点开面板，顶部状态条是绿点 + "无未读"。

## 它长什么样

**日常形态：毛玻璃浮层**（点图标 → 当前网页右侧浮出，用满整屏高度）

```
┌───────────────────────────────────────────┬──────────────────┐
│                                           │ ● ● ●        ×   │
│      你 正 在 看 的 网 页（模糊可见）        │ ┌──────────────┐ │
│                                           │ │  线 上 网 页  │ │
│      浮层是网页文档的一部分，所以           │ │  本 体       │ │
│      backdrop-filter 模糊的是真网页         │ │（聊天/动态）  │ │
│                                           │ └──────────────┘ │
└───────────────────────────────────────────┴──────────────────┘
```

**兜底形态：独立小窗**（`panel.html`，就是 0.1.0 的那个弹窗长相）
在 `chrome://` 内置页、扩展商店、PDF 阅读器等**不允许注入**的页面上，
或者注入失败时自动使用。此时没有毛玻璃（独立窗口同样是不透明的）。

两种形态里都是**整个线上网页**，所以发布动态、回私信、点赞这些**不需要为扩展重写一套 UI**。

## 面板背景（毛玻璃 / 纯色）怎么设置

在 **Moments 网页【我】→「面板背景」**里改：背景模式（毛玻璃/纯色）、底色（跟随主题/深色/浅色）、模糊程度（0–30px）。

设置存在网页的 `localStorage` 里（`moments_panel_bg`），由 `content.js` 转交给扩展存进
`chrome.storage.local`，浮层通过 `chrome.storage.onChanged` **实时**跟上（不用重开面板）。
扩展里**不提供**设置界面 —— 这是使用者明确要求的（开关统一放【我】里）。

⚠️ 网页侧与扩展侧各有一份颜色映射（`src/lib/panelBackground.js` 与 `overlay.js` 的
`panelBgStyle`，扩展没有打包器、import 不到网页代码）。防漂移靠
`scripts/verify-extension-panel.cjs` 里的等价性断言。

## 四个必须知道的限制

**1. 面板点别处 / 按 Esc / 再点一次图标都会关。**
浮层是"临时看一眼"的形态，不是常驻侧边栏（`chrome.sidePanel` 使用者已明确不需要）。

**1.5 权限很小，是有意的。**
浮层靠 `activeTab`：**只有你点图标那一刻**，扩展才临时获得当前标签页的访问权，
平时对其他网站一无所知。manifest 里**没有** `<all_urls>`，
也没有申请 `tabs` 权限。

**2. 不是真实时，是每分钟轮询。**
MV3 的 service worker 空闲约 30 秒就被回收，长连接（websocket）撑不住，所以角标用 `chrome.alarms` 每分钟查一次。**最坏情况角标会晚 1 分钟才变。**

**3. Chrome 关掉就没有了。**
扩展活在 Chrome 里。Chrome 退出，角标和面板都不存在。

> 顺带说明：**系统通知那一层你本来就有**。网页里的 Web Push（`public/sw.js`）在 Chrome 开着时就会全局弹通知，和这个扩展无关。扩展补的是"持久可见的角标"和"不切标签页的操作面板"。

## 角标口径

角标数字 = **未读私信数**（`messages.read_at` 为空）。

动态、评论、点赞**不计入**——那几张表没有"已读"概念，统计不出准确数字，硬做只会得到一个会骗人的角标。

## 工作原理

```
网页（任意标签页 / 浮层里的 iframe / 兜底小窗里的 iframe）
   │  content.js 每 10 秒读一次 localStorage：supabase 会话 + 面板背景设置
   │  改设置时网页 postMessage → content.js 立刻转交
   ▼
background service worker
   │  · 会话存 chrome.storage.local
   │  · chrome.alarms 每分钟查一次未读私信
   │  · access token 过期前 5 分钟自动刷新
   │  · 点图标 → chrome.scripting 注入 overlay.js（activeTab）
   │  · 注入不了 / 浮层报错 → 开兜底小窗 panel.html
   ▼
chrome.action.setBadgeText  →  工具栏角标
chrome.storage.onChanged    →  浮层实时改背景
```

**为什么用 content script 同步会话，而不是让扩展自己登录：**
扩展的源是 `chrome-extension://`，和网页是两个不同的源，读不到对方的 `localStorage`。让 content script 去读（它跑在网页这一侧，同源），就不需要你在扩展里再登录一次。

**⚠️ 一个已知的取舍：refresh token 竞争。**
Supabase 每次刷新都会轮换 refresh token。网页和扩展都能刷新，理论上可能互相作废。当前策略是**以网页为准**：网页同步来的会话会覆盖扩展自己刷新的结果。实践中的风险窗口很小，但如果你遇到"莫名其妙要重新登录"，这是第一个要看的地方。

## 关于 `config.js` 里的 anon key

`config.js` 里的 `SUPABASE_ANON_KEY` **不是密钥，是公开的**——它已经随网页构建产物发布在线上，任何人都能从 bundle 里抠出来。项目的安全边界从来不靠它，而是靠数据库的 RLS。

🔴 **绝对不要把 `service_role` key 放进扩展。** 它是唯一能绕过全部 RLS 的钥匙，放进来等于把所有私聊和动态交给任何能读到这个文件的人。这条与仓库根 `AGENTS.md` 的硬约束第 1 条一致。

## 疑难

| 现象 | 原因 / 处理 |
|---|---|
| 角标一直是空的 | 先确认网页登录过（状态条会提示"未同步会话"）；确认图标已固定到工具栏 |
| 状态条显示"未同步会话" | 打开一次 Moments 网页即可，扩展会自动同步 |
| 状态条显示"同步异常" | 大概率是网络；点 ↻ 重试。持续失败就去 `chrome://extensions/` 点扩展的 "Service Worker" 看日志 |
| 改了代码不生效 | 到 `chrome://extensions/` 点该扩展的刷新按钮；改 `manifest.json` 必须重新加载 |
| `chrome://` 页面上点图标开的是小窗 | 这是设计如此：这些页面不允许注入浮层，自动走兜底 |
| 面板里网页加载不出来 | 浮层里会给出提示和「在独立窗口打开」按钮；多半是网络/站点问题 |
| 面板里没登录 | 面板嵌的是线上网页，登录态取决于上面那个「iframe 与标签页是否共享存储」的实测结论 |

## 验证

```bash
node scripts/verify-extension.cjs        # 角标 / 会话同步 / token 刷新 / 兜底小窗
node scripts/verify-extension-panel.cjs  # 毛玻璃浮层本身（39 项断言）
```

`verify-extension-panel.cjs` 会自建本地 HTTP 测试页，验证：真毛玻璃（`backdrop-filter`
作用在宿主网页上）、Shadow DOM 隔离、Esc/点外部/×/再点图标的四种关法、设置实时生效、
color 映射不漂移、CSP 页面照样能加载、"网页加载不出来"时给提示且**不自动弹窗**。

⚠️ 它用一份**测试副本**扩展（只在 manifest 里多一条 `http://127.0.0.1/*` 主机权限）：
真机上注入靠"点图标授予的 activeTab"，而 **Playwright 点不到浏览器工具栏**。
因此"点图标是否真能授予 activeTab"这条只能真人在真机上点一下确认（见 docs/STATUS.md 验收清单）。
脚本里另有一条断言盯着**真扩展**的 manifest 授权保持最小。

**注意：它会创建 `@example.com` 测试账号，跑完要用 `node scripts/cleanup-test-data.cjs` 清理。**
